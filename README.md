# 足球人生 · Football Life

> **v1128.2 版本说明**：FM 式 0~200 CA 体系（联赛均值 中乙100/中甲130/中超150）、出身创建向导（青训/天才/家乡）、领域配比属性分配、比赛事件与评分重构、赛季成绩单（D~S 分级）、美漫画风 UI、身价真实货币化、联赛规范化命名（中超/中甲/中乙）。

一个纯前端、无依赖的足球生涯模拟游戏。从 16 岁起步，通过训练、比赛、转会和赛季推进走向退役。

## 运行方式

直接双击 `index.html` 即可（使用普通 `<script>`，兼容 `file://`）。

如果希望用本地服务器：

```powershell
python -m http.server 8000
# 然后打开 http://localhost:8000
```

## 目录结构

```
Game/
├─ index.html          页面结构：创建页 / 主界面四宫格 / 各功能弹层
├─ assets/
│  └─ style.css        全部样式
├─ js/
│  ├─ data.js          静态配置：属性、联赛、训练、比赛事件、成就、文案
│  ├─ engine.js        仿真引擎：状态、成长、比赛、赛季、转会、存档槽
│  └─ ui.js            UI 层：DOM 绑定、面板、渲染、存档槽、比赛逐步播放
└─ README.md
```

脚本按 `data.js → engine.js → ui.js` 顺序加载，使用全局作用域共享状态与函数；这样无需构建工具，也避免了 `file://` 下 ES Module 的跨域限制。

## 主要可调位置

### 属性与成长（`js/data.js`）

- `ATTRS_BY_POS`：**每个位置独立的 10 项属性表**（参考 FM27 属性与职责体系做的简化）。其中速度 / 耐力 / 力量三项为位置通用的“身体素质”，其余属性按该位置的角色职责方向设计：
  - 前锋：终结、冷静、跑位、技术、传球、视野、头球 + 身体三项
  - 中场：技术、传球、视野、决断、射门、冷静、防守 + 身体三项
  - 后卫：技术、传球、决断、防守、位置感、头球、冷静 + 身体三项
  - 门将：反应、手型、制空、选位、决断、传球、技术、冷静 + 耐力 / 力量
- `ATTR_LABEL` / `ATTR_GROUPS_BY_POS`：属性中文名与按位置分组的展示（技术 / 精神 / 身体）。
- `ATTR_START`：各位置初始能力区间（1–20），键必须与该位置属性表一致。
- `ATTR_WEIGHTS`：位置综合能力权重，每行覆盖该位置全部属性且合计 1.0。
- `ATTR_XP_BASE` / `XP_GROWTH`：各项属性各自的升级经验基数与成长曲线（`XP_GROWTH=1.45`，FM 式指数成本：每升 1 级所需经验 ×1.45，等级越高越贵）；界面不显示经验数字。
- `POS_CORE_ATTR`：每个位置的核心属性（如前锋的终结），高龄衰减时优先保护。

### 联赛评级（星级，FM CA 逻辑）

属性面板：**综合 / 潜力评价用星级**，顶部摘要同时显示**体能 / 状态百分比**（原“比赛发挥”已移除）；下方每个具体属性显示 FM 的 **1~20 原始数值**（色阶：1–5 灰、6–10 白、11–15 黄、16–20 绿）。

- `LEAGUE_QUALITY`：3 级联赛（甲A / 甲级 / 乙级）的球员质量正态分布 `mean / sd`。联赛平均水平每个赛季随机波动 ±20%（引擎写入 `G.seasonMeanMul`，在 `advanceSeason()` 中重掷）。
- `ATTR_NORM`：各属性相对联赛均值的画像系数（如速度略高、终结略低），避免所有属性都按同一均值评判。
- 星级换算：**50% 分位 = 3★，每 10% 分位 ±0.5★**（`normCdf` → `starsFromPct`，范围 0.5★–5★）。同一球员在低级别联赛星级更高（如鱼得水），升班马到高级别联赛则评级下滑。
- 综合 / 潜力同样按联赛分位显示星级（综合的分布方差按 `sd×0.8` 收窄）。

### 训练（天数制，`js/data.js` + `js/engine.js`）

- `TRAIN_CATS`：**按位置职能设计**，每个位置 3 个角色职责方向 + 身体素质 + 综合训练（共 5 个模块，第 5 个占满一行不留空格）：
  - 前锋：创造机会 / 把握机会 / 支点能力 / 身体素质 / 综合训练
  - 中场：组织调度 / 攻坚插上 / 防守拦截 / 身体素质 / 综合训练
  - 后卫：出球组织 / 防空拦截 / 卡位对抗 / 身体素质 / 综合训练
  - 门将：扑救反应 / 制空出击 / 发动进攻 / 身体素质 / 综合训练
- **通用逻辑（FM 式）**：训练对该位置**全部属性等权重**发放经验；当训练组合命中 `TRAIN_FOCUS[训练ID]` 中的重点属性时，这些属性权重 ×`FOCUS_BOOST`（1.8）。**综合训练（`general`）无重点属性 = 纯等权**。
- **天数选择 0~6**（`WEEK_DAYS=6`，一周一赛）：训练 d 天 + 休息 (6−d) 天。
  - 体能结算 = 上场剩余体能 + 休息恢复（`FIT_RECOVER_PER_DAY`×休息天数）− 训练消耗（`cat.cost × TRAIN_COST_PER_DAY_MUL × 天数`）。
  - 成长不随天数线性放大：第 1 天为基准（`DAY_XP_DECAY[0]=1`），之后按 `DAY_XP_DECAY=[1,0.85,0.75,0.7,0.65,0.6,0.55]` 逐日边际递减，**6 天合计 4.55×**（日均 0.76，衰减温和）。
- **训练面板预览为单行格式**：`（把握机会）终结++ 冷静++ 跑位++`（综合训练显示 `全属性+`），另附一行体能/成长/**学习**/状态摘要。
- **学习倍率 `learnMul(G)`**：随「所在联赛水平 vs 自身能力」缩放——**3★（联赛平均）= 1.0 基准**，能力越低倍率越高（能学的多，上限 1.8），能力越高倍率越低（没什么可学，下限 0.4）。训练与比赛成长共用该倍率，训练提示与预览中显示 `学习 ×X.X`。
- **比赛通用成长**：参赛即对全部属性等权发放经验，系数与评分、出场时间挂钩——**6.0 评分 / 90 分钟 = `MATCH_GROWTH_BASE`（1.0）× 1 天训练基准**（`TRAIN_DAY_XP=2`），按 `rating/6.0 × minutes/90` 缩放，并同样乘 `learnMul` 与 `ageFactor`。
- 改动训练平衡优先调 `TRAIN_DAY_XP` / `MATCH_GROWTH_BASE` / `XP_GROWTH` / `DAY_XP_DECAY` / `TRAIN_COST_PER_DAY_MUL` / `TRAIN_FOCUS` / `ATTR_XP_BASE`，不要改 UI。当前参数下的成长节奏（满训上限仿真）：5 场 ≈ 开局星级、12 轮 ≈ +0.5★、赛季末 ≈ 2.5~3★、乙级 5★ 中位需 4 调（默认 3 天训练更慢）。

### 状态（form，`js/data.js` + `js/engine.js`）

状态与**训练天数、上场时间**直接挂钩（`FORM_*` 常量），并决定比赛发挥（`formF = 0.82 + form×0.36`，同时进入事件成功率）：

- 每训练 1 天：+0.055（训练的状态收益，随天数累计）；每 90 分钟出场：+0.07。
- 一周 0 天训练：−0.09；整场坐替补席：−0.08（两者叠加 = 大量损失）。

### 体能（`js/data.js` + `js/engine.js`）

- `prepareMatchFitness()`：本周未训练时，按 6 个休息日全额恢复；已训练则由 `doTraining()` 完成“恢复 − 消耗”结算。
- `matchFullCost()`：满场体能消耗，按位置与耐力属性计算；比赛按实际出场分钟扣除。

### 比赛（`js/data.js` + `js/engine.js`）

- `POS_EVENT_WEIGHTS`：各位置抽到进攻/组织/防守/扑救事件的权重（事件池只保留有权重的类型）：

  | 位置 | 进攻 attack | 组织 pass | 防守 defend | 扑救 save |
  |---|---|---|---|---|
  | 前锋 | 0.60 | 0.40 | —（无防守事件） | — |
  | 中场 | 0.30 | 0.40 | 0.30 | — |
  | 后卫 | 0.15 | 0.10 | 0.75 | — |
  | 门将 | — | — | — | 1.00（全部为扑救） |

- `MATCH_EVENTS`：按位置组织的关键事件池（`MATCH_EVENTS[位置][类型]`），`need` 只引用该位置属性表内的键。
- `POS_DEF_NEED`：按位置取可用属性计算防守综合能力，用于对手期望进球。
- **事件成功率** = 球员关键属性（含体能系数）相对**当前联赛平均水平**的差值 + 状态修正：高水平球员在低级别联赛如鱼得水，升班马则处处受制。进球期望同样与联赛均值比较。
- `simMatch()`：返回结构化 `beats`，由 UI 逐环节播放；每半场 5 次关键点，实时评分、比分、体能消耗、换人判定。
- **出场逻辑（`appearancePlan`）**：按综合星级分档，叠加近期表现 `perfAvg`（EMA，每场 `0.55×旧 + 0.45×本场评分`，未登场向 6.0 收敛；**首秀直接取本场评分，未首秀时 `perfAvg=0`、界面显示 —**，计算时回退 6.3 中性基准）：
  - **< 1.5★ 边缘球员**：首发率 0.12，无替补登场机会；
  - **≥ 1.5★ 替补档**：开始有替补登场机会（登场率 0.45~0.9），表现好 → 首发率与替补登场稳定性提升，甚至竞争首发（首发率 0.15~0.6）；
  - **≥ 2.5★ 稳定首发**：首发率 0.7~0.98，预期 90 分钟；
  - **≥ 3.5★ 忽略评分**：首发率 0.99，**免疫换下判定**（半场体能/评分换下均不生效），尽量踢满全场。
- 换人规则（<3.5★）：过了半场后，连续两个关键点实时评分低于 6.0，或关键节点体能低于 40，即被替换下场。
- **预期上场时间** = 首发概率 × 首发平均分钟 + (1−首发概率) × 替补登场率 × 替补平均分钟，四舍五入到 5 分钟：
  - 首发平均分钟：tier3 = 90（不被换下）；其余档 85（存在被换下风险）；
  - 替补登场时间 U(56,80) → 平均第 68 分钟上场、实际踢 22 分钟；
  - 示例：边缘 10 分钟（0.12×85）· 替补档 35 分钟 · 主力 75 分钟（0.88×85）· 核心 90 分钟。
- 完全未登场时评分固定 6.0，且不计入场均评分。

### 生涯数据同步

- `recordMatch()`（`js/engine.js`）：**每场比赛结束后**立即把出场/进球/助攻/评分写入 `seasonStats` 与 `careerStats`，生涯面板无需等到赛季结算。
- `advanceSeason()` 只写入赛季履历（`history`），不再重复累加生涯数据。

### 赛季命运（升降级与球队事件，`seasonFate()`）

赛季结算时按「球队排名 × 个人数据」判定（`playerGood` = 场均 ≥6.4 且出场 ≥5；`playerBad` = 场均 <5.9 或出场 <5；其余中性——本作评分标尺偏严，赛季场均中位约 5.9~6.4）：

| 球队成绩 | 你数据差 | 你数据中性/好 |
|---|---|---|
| 前 3（好） | **出售 / 租借事件**（玩家自选去留） | **大概率随队升级（0.8）**；冲超失败且数据好 → 上级俱乐部求购 |
| 4~14（一般） | 无事件 | **高一级球队求购事件**（去/不去自选，顶级联赛除外） |
| ≥15（差） | **一起降级**（17 名起 0.95，15~16 名 0.60） | 数据好则大幅降低降级概率（0.55 / 0.25），中性 0.80 / 0.45 |

- 报价类型 `kind`：`contract`（合同到期）/ `upgrade`（求购）/ `sell`（挂牌出售）/ `loan`（租借 1 年）；报价面板按类型显示标签与按钮文案。
- **租借**：接受后记录母队 `G.onLoan`，租借赛季结束自动归队（履历标记“租借”）；租借期内接受永久转会则中断租借不再归队。
- 接受任何报价后 `syncSeason()` 按新联赛重排赛程；读档时若存档留有未处理报价会补显。
- 报价优先级：赛季命运事件 > 合同到期续约（`genOffers`）。

### UI / 页面

- `index.html`：主界面四个方格——上排 属性 / 训练，下排 **下一场**（div，不可点）/ **右下格为数据、生涯两个约半高的长方框垂直排列**（等分格高、中间留 10px 间隔，各自独立点击）；底部比赛操作条；顶栏“菜单”按钮返回开始菜单（自动保存）。
- **出场方格**：显示下一场预期定位（边缘球员 / 替补待命 / 首发竞争 / 主力首发 / 首发核心）与**预期上场时间**，脚注为“综合 X★ · 近期均评 X.X”（**未首秀显示 —**）。
- **数据半高框**：`X场 · X球 · X助 · 均评 X`，点击进入数据面板；**生涯半高框**：`第X赛季 · 年龄 · 冠军数 · 声望（按 repClass 等级配色）`，点击进入生涯面板；面板间仍有“查看生涯 / 查看数据”互跳按钮。
- 创建页：场上位置只列 前锋 / 中场 / 后卫 / 门将；“足球起点”随位置切换为对应的职责名称（无提示性描述）。
- 训练面板：模块按钮 5 个（无 emoji 图标），第 5 个“综合训练”占满一行；预览为单行重点属性格式 + 体能/成长/状态摘要。
- 顶栏：只显示 综合 / 身价 / 声望（**无具体数值，文字按 `repClass` 等级配色**）；体能只显示百分比（无“发挥 100%”表述）；无“有效 X.X★”。
- 成就入口在右上角“成就”按钮；`fitTiles()` 按可视高度收缩四宫格（两行等高，右下格内两个半高框再二等分）。
- 比赛层一次只显示当前环节；进球/助攻/扑救徽章为纯文字（进球 / 助攻 / 扑救 / 关键防守）。
- **全站无 emoji**（星级 ★ 与排版箭头除外），已纳入回归测试扫描。
- 底部“模拟下一场”会按当前天数选择自动训练并快速结算。

### 已移除的系统

- 伤病（`injuryWeeks`）、士气（`morale`）、训练强度（轻度/普通/强化）均已移除；旧存档读取时自动清理这些字段。

## 存档

使用浏览器 `localStorage`，**5 个存档栏位**（键名 `football_life_slot_1` ~ `football_life_slot_5`）：

- 创建新角色时自动写入第一个空栏位；栏位已满时弹出选择层，可**替换某个栏位**或**放弃本次存档**（放弃后本局不保存）。
- 开始菜单“读取存档”列出全部栏位（名字 / 位置 / 赛季 / 俱乐部 / 保存时间）。
- 关闭或刷新页面时自动保存当前栏位（`beforeunload`）；顶栏“菜单”返回开始菜单时也会先保存。
- 旧单档 `football_life_save_v1` 首次启动时自动迁入栏位 1。

### 存档迁移（`migrateSave`）

按 `attrVersion` 逐级升到 3：20–99 制换算到 1–20 制 → 旧的 6 属性扩展为 12 属性 → 按当前位置映射到新的按位置属性表（如门将的旧“防守”→“反应”、“头球”→“制空”、“决断”→“选位”），清理不属于该位置的旧键，删除伤病 / 士气 / 强度等已废弃字段，补齐天数、联赛波动、`perfAvg`（近期表现，**默认 0 = 未首秀**）等新字段。

## 开发提示

- 修改静态配置优先只改 `js/data.js`。
- 修改行为逻辑改 `js/engine.js`，不要把 DOM 操作写进引擎。
- 修改展示、面板、按钮交互改 `js/ui.js`。
- 三个脚本均为经典脚本，新增文件时保持加载顺序并在 `index.html` 中追加 `<script src="...">`。
